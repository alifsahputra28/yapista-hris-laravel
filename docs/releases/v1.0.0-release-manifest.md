## Security And Storage

- Employee NIK: Laravel encryption plus HMAC SHA-256 blind index; exact lookup only.
- QR: random/revocable token; encrypted raw token and hash storage; no identity payload.
- Legacy attendance compatibility: exact 10-digit `employees.employee_number` is accepted only by the scanner resolver when `ATTENDANCE_ALLOW_LEGACY_NUP_QR=true`; it records method `qr` and uses the same attendance business rules.
- New E-Card/card issuance remains secure-token-only. Legacy NUP fallback is transitional, predictable, and scheduled for retirement after physical cards are replaced.
- Documents/photos: private storage plus authorized controller/policy access.
- Public employee runtime files: 0; public storage contains only `.gitignore`.
- Private quarantine: 6 legacy employee binaries plus 1 manifest; ignored by Git; permanent deletion 0.
- Public forbidden artifacts audit: 0 `.env`, SQL dump, backup, debug log, or `phpinfo` file.
- Admin/HR Employee Detail exposes the complete authorized master profile using existing relationships and progress service. Sensitive identifiers are masked; raw QR/token/hash, ciphertext, and private paths are excluded. No migration was introduced.
- Attendance scanner Focus Mode is selected server-side in the shared Mantis layout. Scanner pages omit Admin sidebar/header/breadcrumb/footer, while Dashboard, employee list, and event list retain normal navigation. HID Enter, autofocus/refocus, secure/legacy resolver behavior, authorization, and duplicate protection remain intact.
- System-wide Indonesian UI copy is standardized across roles and major modules. Authentication/validation default to locale `id`; internal identifiers and business behavior remain unchanged. The terminology source of truth is `docs/ui/system-copywriting-guideline.md`.
- Invitation onboarding is role-aware: verified employees keep their official identity and active QR while using a compact optional three-step profile review; new employees without NUP retain the six-step submission and HR approval workflow. Employee profile requests cannot change official employment fields or trigger re-verification for verified employees.
- Onboarding change-impact regression: 145 tests / 1.263 assertions PASS. Authenticated invitation, wizard, profile mutation, verification, QR preservation, and dashboard guidance were exercised through feature tests without reprovisioning a UAT credential.
- New-employee onboarding uses a server-rendered focus mode in the shared Mantis layout. Its six-step wizard and related CRUD subforms omit portal navigation while retaining shared assets, logout, and confirmations. Existing verified employees continue to render normal employee navigation. Focus-layout tests passed 35 tests / 318 assertions and read-only browser QA passed at 1440x900 and 390x844.
